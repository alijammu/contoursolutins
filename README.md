# Consort Technologies

Consort Technologies website, reconstructed from the public frontend of https://htechsupports.com/ captured on October 13, 2026. The original layout, theme CSS, imagery, navigation, and browser scripts are retained. The company name and temporary wordmark have been updated; source company contact details and social links still need the business's replacements.

## Run

Requires Node.js 20 or later. No package installation is needed.

```sh
npm run build
npm start
```

Open http://localhost:4173. `PORT` can select another port. The preview listens on this computer only.

## Files

- `site-source/`: versioned public page and asset snapshots with blog spam comments removed; sufficient to rebuild from a fresh clone.
- `archive/`: original local downloads, excluded from Git. After a new capture, run `node tools/prepare-source.mjs` to refresh the versioned source.
- `dist/`: the locally linked, editable website. Generated by the build command.
- `branding.json`: name, abbreviation, contact addresses, logo paths, optional primary color, exact text replacements, and URL replacements for white-labeling. Update it and rebuild.
- `src/`: local form handling and compatibility styles.
- `tools/`: repeatable capture, build, preview server, and verification scripts.
- `capture-report.json`: captured pages, unavailable assets, and known limits.
- `screenshots/`: browser verification images, when available.

To use a replacement logo, put it in `src/assets/`, set the corresponding path in `branding.json` to `/assets/your-logo.png`, and rebuild. The current logo is a temporary Consort Technologies wordmark. Use `textReplacements` for office addresses and other copy, and `urlReplacements` for the hub and social URLs. Review the original client logos, service claims, office addresses, legal text, and case studies when adapting the site to the next business.

## Forms and limits

Contact and partner forms save inquiry data to `data/submissions.jsonl` through the local server. They display a clear local-save confirmation. They do not email H-Tech Supports. File uploads require a future backend integration.

This is a static frontend reconstruction. Public downloads cannot include WordPress PHP code, admin access, the database, email integrations, or private portal functionality. Original external social and hub links are preserved until replaced. Maps and external links may need internet access. Some image links were already unavailable at the source; they are listed in the capture report. Blog spam comments are retained only in the original archive and removed from the local build.

Use `npm run check` to audit local page references. `npm run capture` refreshes public downloads and may need network approval; it preserves previously downloaded records.

## GitHub Pages

The site can be hosted on GitHub Pages as a static website. After building, export with the intended repository name:

```sh
npm run export:pages -- --base=/your-repository-name/
```

If the local npm installation is unavailable, run `node tools/export-pages.mjs --base=/your-repository-name/` directly.

For an account site (`username.github.io`) or custom domain, use `--base=/`. The publishable files are in `deploy/github-pages/`, including `.nojekyll`. Publish those files through GitHub Pages; the original archive and local inquiry data are not included in the export. The exporter adjusts local page, image, CSS, script, and responsive image paths to the repository path.

GitHub Pages does not run the Node.js server. Exported forms explicitly report that online submissions are not connected; a hosted form endpoint or separate backend is required before accepting live inquiries. No repository has been created and no site has been published by this export command.

The repository includes a manual **Deploy GitHub Pages** workflow. To publish, select **GitHub Actions** in the repository's **Settings → Pages**, then run the workflow from **Actions**. Pushing code alone does not start a deployment. The workflow derives the repository path automatically. No npm installation step is required because the build has no third-party dependencies.
